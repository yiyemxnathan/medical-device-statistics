# 医疗器械研发与质量统计分析本地部署程序设计

## 背景与目标

本系统面向医疗器械研发和质量部门，提供本地部署的数据统计分析与抽样检验工具。第一版定位为“受控记录工具”：程序直接生成可归档报告，并记录输入数据、计算参数、标准表版本、算法版本、操作者和时间戳。

系统采用质量与研发一体化设计，覆盖计数型抽样检验、OC 曲线、抽样计划与接受准则，以及研发常用统计检验。第一版不做完整电子签名和验证包，但为后续接近 QMS 受控软件要求预留审计、权限、算法版本和标准数据包管理接口。

## 范围

### 第一版包含

- 本地 Web 应用，可单机运行，也可部署到局域网服务器。
- 项目、数据集、分析任务、报告、审计日志和系统设置。
- ISO 2859 / GB/T 2828 计数型抽样检验。
- 正常、加严、放宽检验状态的转换规则框架。
- 样本量字码、样本量、Ac/Re、接收概率和 OC 曲线输出。
- 描述统计、正态性检验、方差齐性检验。
- 单样本、双样本、配对 t 检验。
- 非参数检验、单因素 ANOVA、简单线性回归。
- HTML 预览和 PDF 导出的受控报告。
- 数据集版本化、报告冻结、逻辑作废和基础审计日志。

### 第一版不包含

- 计量型抽样检验。
- MSA / GR&R。
- DOE。
- SPC 控制图。
- 过程能力 Cp/Cpk。
- Weibull 可靠性分析。
- 等效性/非劣效检验。
- 规格限通过率。
- 样本量估算。
- 21 CFR Part 11 深度电子签名与完整验证包。

这些功能作为二期或后续模块扩展。

## 标准版本与数据来源

系统支持标准版本和标准表数据包版本管理。ISO 官网显示 ISO 2859-1:2026 已发布；GB/T 2828.1 常见当前版本为 GB/T 2828.1-2012。由于标准表格通常受版权限制，第一版不把标准表硬编码为不可替换的唯一数据源，而是提供标准数据包导入、启用、停用和版本锁定能力。

历史分析和报告引用当时启用的标准数据包版本。后续标准更新不会导致历史报告重算。

## 推荐架构

系统采用受控记录型 Web 应用架构：

- 前端：React。
- 后端：Python FastAPI。
- 数据库：SQLite 用于单机和小团队部署，PostgreSQL 用于局域网多人部署。
- 统计计算：SciPy、statsmodels、pandas、numpy。
- 图表：前端渲染结构化图表数据，后端负责关键计算。
- 报告：后端生成 HTML/PDF 报告快照。

前端负责交互、数据选择、图表展示和报告预览。后端负责参数校验、抽样计划计算、统计检验、报告生成和审计留痕。关键计算不在浏览器执行。

## 功能模块

### 项目与数据集

项目用于承载产品、物料、供应商、批次、试验或验证活动等业务上下文。用户可以在项目下导入 CSV、Excel 或粘贴表格数据。

每次导入生成不可变的数据集版本。系统保存原始文件哈希、导入人、导入时间、字段结构、数据类型和数据摘要。后续分析任务必须引用具体数据集版本。

### 抽样检验

抽样检验模块以计数型抽样为核心。用户输入标准版本、批量、检验水平、AQL、检验状态和抽样方案类型。系统输出样本量字码、样本量、Ac/Re 接收准则、接收概率和 OC 曲线。

用户可以记录实际抽检结果，系统根据不合格品数或缺陷数判断接收或拒收。若标准表查不到输入组合，系统返回明确错误，不自动近似。

正常、加严、放宽转换规则在第一版作为框架实现，记录当前检验状态、转换依据和状态变更历史。具体转换细节由标准数据包和企业程序文件配置。

### 研发统计分析

统计分析模块覆盖：

- 描述统计。
- 正态性检验。
- 方差齐性检验。
- 单样本 t 检验。
- 双样本 t 检验。
- 配对 t 检验。
- 置信区间。
- 非参数检验。
- 单因素 ANOVA。
- 简单线性回归。

系统自动生成统计表、图表、假设检查结果和解释性文本。解释文本用于辅助分析，不替代产品放行、设计验证或质量决策结论。

### 报告

报告模块支持抽样计划报告、抽检结果报告和统计分析报告。报告包含报告编号、生成时间、操作者、项目、数据集版本、分析参数、结果、图表、标准表版本、算法版本和软件版本。

报告生成后冻结为快照。后续数据、标准表或算法升级不改变历史报告。报告作废采用逻辑作废，需要记录作废原因、操作者和时间。

### 审计与受控记录

审计日志记录关键动作：

- 数据导入。
- 分析任务创建。
- 分析参数变更。
- 报告生成。
- 报告作废。
- 标准表版本启用或停用。
- 用户权限变更。

审计日志只读，不允许编辑。第一版不做完整电子签名，但保留扩展字段。

### 系统设置

系统设置包括：

- 基础用户角色：管理员、分析人员、只读查看。
- 标准表数据包管理。
- 报告模板管理。
- 单机或局域网部署配置。
- 软件版本和算法版本展示。

## 数据流

1. 用户导入 Excel、CSV 或粘贴表格。
2. 系统执行字段识别、类型校验、缺失值检查和数据摘要。
3. 用户确认后生成不可变数据集版本。
4. 用户基于数据集版本创建抽样或统计分析任务。
5. 后端保存所有显式参数，并使用固定算法版本计算结果。
6. 后端返回结构化结果、图表数据、解释文本和警告信息。
7. 用户复核结果后生成报告。
8. 系统保存报告快照，并写入审计日志。

若用户修改参数，系统创建新的分析任务，不覆盖旧任务。

## 错误处理

系统对以下情况返回明确错误或警告：

- 输入数据为空。
- 字段类型不匹配。
- 缺失值影响计算。
- 样本量不足。
- 方差为零。
- 分组不足。
- AQL、检验水平、批量或检验状态组合不存在。
- 正态性、方差齐性或其他检验前提不满足。
- 标准数据包未启用。
- 报告引用的数据集版本或分析结果不存在。

统计前提不满足时，系统不静默输出确定性结论，而是显示假设检查警告和可选替代方法。

## 计算可信度

核心计算由后端完成，并记录软件版本、算法版本、统计库版本和标准数据包版本。

抽样 OC 曲线使用可解释的概率计算方法。第一版支持二项分布路径，有限批量场景可扩展超几何分布路径。报告中标注使用的计算方法。

统计检验调用 SciPy 和 statsmodels。核心算法建立单元测试，与手工样例、公开示例或已确认的参考结果比对。

## 界面结构

程序打开后直接进入工作台，不做营销型首页。

- 左侧导航：项目、数据集、抽样检验、统计分析、报告、审计日志、设置。
- 项目页：按产品、物料、批次、试验筛选，并查看关联数据集、分析任务和报告。
- 数据集页：导入、校验、预览和查看版本。
- 抽样检验页：向导式输入，右侧实时展示样本量、Ac/Re 和 OC 曲线。
- 统计分析页：选择数据集、变量、分组和检验方法，展示统计表、图表、假设检查和解释文本。
- 报告页：查看历史报告、HTML 预览、PDF 导出和报告作废。
- 审计日志页：按对象、用户、动作和时间筛选。
- 设置页：标准表数据包、用户角色、报告模板和部署配置。

## 测试验证

第一版测试分五层：

- 核心算法测试：抽样计划查表、Ac/Re、OC 曲线概率、t 检验、方差检验、ANOVA、非参数检验和回归结果。
- API 测试：参数校验、错误返回、报告冻结和审计日志写入。
- 数据完整性测试：数据集版本不可变、报告引用固定版本、逻辑作废不删除历史。
- 前端流程测试：导入数据、创建抽样计划、创建统计分析、生成报告。
- 验证样例集：内置可手工复核的小样例，用于版本升级回归测试。

## 部署

单机版使用 FastAPI、React 和 SQLite，可通过本地安装或 Docker Compose 运行。

局域网版使用 FastAPI、React 和 PostgreSQL，通过 Docker Compose 部署到内网服务器，用户通过浏览器访问。

系统需要支持数据库备份、标准表数据包备份和报告文件备份。版本升级时保留数据库迁移记录，历史报告不重算。

## 设计决策摘要

- 选择质量与研发一体版，而非单一抽样或单一统计工具。
- 选择本地 Web 架构，兼容单机和局域网部署。
- 选择受控记录工具定位，报告可归档并可追溯。
- 抽样第一版聚焦计数型抽样和正常、加严、放宽框架。
- 研发统计第一版覆盖基础检验和增强分析，不覆盖验证级等效性和样本量估算。
- 选择 React + FastAPI + SQLite/PostgreSQL + SciPy/statsmodels 的实现路线。
